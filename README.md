# POS: Oracle Database + Express + React

Касса работает с Oracle Database как основной БД. Сервер использует официальный Node.js-драйвер `node-oracledb` в Thin mode, поэтому Oracle Instant Client для Node.js не нужен. Требуется запущенный Oracle Database Free и отдельный пользователь схемы POS.

## Что входит

- Касса, смены, продажи за наличные/картой/в долг, клиенты и склад.
- Складские приходы, инвентаризация и журнал движения товара.
- Отчёты и аналитическая панель: выручка, валовая прибыль, средний чек, сравнение с предыдущим периодом, разбивка по способу оплаты, рейтинги, фильтры и экспорт CSV.
- Объяснимые подсказки о пополнении запасов, низкой марже и товарах без продаж.
- Чат Oracle для вопросов об аналитике. Он получает только агрегированные показатели и историю диалога, не получает телефоны и имена клиентов и не выполняет SQL.

## Локальный запуск Oracle Database

Нужен Docker Desktop с Compose. Если `.env` ещё нет, создайте его копией `.env.example`; если файл уже есть, сохраните действующие настройки и добавьте/обновите в нём Oracle-переменные. Задайте уникальные пароли для Oracle администратора и пользователя POS. Файл `.env` не добавляйте в Git.

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# Откройте .env и установите собственные значения ORACLE_SYS_PASSWORD, ORACLE_PASSWORD и JWT_SECRET.
docker compose -f docker-compose.oracle.yml up -d oracle-db
```

Официальный контейнер Oracle Free создаёт службу `FREEPDB1` и сохраняет данные в томе `pos-oracle-data`. При первой инициализации Oracle может запускаться несколько минут. После сообщения `DATABASE IS READY TO USE!` создайте/обновите пользователя POS и выдайте ему права на собственную схему:

```powershell
docker exec pos-oracle-db bash /opt/oracle/scripts/setup/01-create-pos-user.sh
```

Конфигурация Node.js находится в `.env`:

```env
ORACLE_USER=pos_app
ORACLE_PASSWORD=<тот же пароль, что задан для контейнерного пользователя POS>
ORACLE_CONNECT_STRING=localhost:1521/FREEPDB1
```

После готовности контейнера примените схему и создайте администратора:

```powershell
npm install
npm run db:migrate
npm run user:create
npm start
```

Команда создания пользователя запросит имя, пароль и роль `admin`. Для кассиров используйте роль `cashier`.

### Перенос текущих данных из SQLite

Перед переключением сохраните резервную копию старого файла SQLite. После применения схемы Oracle и до создания пользователей/рабочих данных можно однократно импортировать таблицы старой POS-базы:

```powershell
npm run db:import-sqlite
```

По умолчанию скрипт ищет `data/pos.sqlite`; другой путь задаётся через `LEGACY_SQLITE_PATH`. Импорт разрешён только в пустую Oracle-схему, сохраняет связи и идентификаторы, после переноса синхронизирует identity-генераторы. Источник открывается только для чтения и не удаляется.

## Клиент React

```powershell
cd client
npm install
Copy-Item .env.example .env
npm run dev
```

Откройте `http://localhost:5173`. Для production используйте `npm run build` из `client`.

## Чат Oracle

Серверный чат использует OpenAI Responses API. Укажите ключ в серверном `.env`, затем перезапустите API:

```env
OPENAI_API_KEY=<ваш ключ>
OPENAI_MODEL=gpt-5-mini
```

Ключ остаётся на сервере и не попадает в браузер. Запросы чата не сохраняются провайдером (`store: false`). В AI передаются выбранный период, сводные показатели, агрегированные показатели отдельных товаров и вопрос администратора. Транзакции и персональные данные покупателей не отправляются. Если ключ не задан, аналитическая панель и правила-рекомендации продолжают работать. При ошибке исчерпанной квоты чат формирует ограниченную локальную сводку из тех же агрегированных данных на пять минут, обозначает её как локальный ответ и временно не повторяет запросы к AI-провайдеру.

## Настройка времени и безопасности

Часовой пояс приложения по умолчанию — `Asia/Aqtau`. Oracle хранит отметки с часовым поясом; отчёты группируют календарные дни по Актау. Можно переопределить `APP_TIME_ZONE`. Установите собственные `JWT_SECRET`, `ORACLE_PASSWORD` и `ORACLE_SYS_PASSWORD`; не публикуйте `.env`, резервные копии базы и API-ключ.

## Основные API

- `POST /api/auth/login`, `GET /api/auth/me`
- `GET/POST /api/products`, `PUT/DELETE /api/products/:id`
- `POST /api/shifts/open`, `GET /api/shifts/current`, `POST /api/shifts/close`
- `POST /api/sales`, `GET /api/sales`, `GET /api/sales/:id`
- `GET/POST /api/customers`, `POST /api/customers/:id/pay-debt`
- `GET/POST /api/warehouse/documents`, `POST /api/warehouse/documents/:id/complete`, `POST /api/warehouse/inventory`
- `GET /api/reports/daily`, `/api/reports/monthly`, `/api/reports/top-products`, `/api/reports/analytics`
- `GET /api/analytics/chat/status`, `POST /api/analytics/chat`

Аналитика `/api/reports/analytics` принимает фильтры `date_from`, `date_to`, `category`, `cashier_id`, `unit`, `payment_type` (`cash`, `card`, `debt`) и `stock_status`. Сравнение сопоставляет выбранный интервал с таким же предыдущим интервалом по календарному времени Актау. Ответ содержит рейтинг категорий и ABC-классы товаров по накопленному вкладу в выручку: A — около 80%, B — следующие 15%, C — остальные товары. Разбивка оплаты относится к чекам в выбранном периоде; последующие оплаты долгов показываются в денежных отчётах по дате фактического поступления. Маржа по проданным товарам основана на сохранённых в строках чека цене и себестоимости, с пропорциональным распределением скидки. Дни запаса — оценка по средним продажам выбранного периода, а не прогноз с учётом будущего спроса.

Все денежные значения хранятся целыми числами в тиынах. Поле отчётов `net_profit` исторически означает валовую прибыль после себестоимости и скидок; расходы вроде зарплат и аренды в системе пока не учитываются.
